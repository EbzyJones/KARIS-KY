## Summary

Documents the event `withdraw` emits in both event docs (#513, second scope item). This PR implements that single instruction; #511, #512 and #514 are referenced but not implemented here. Docs only, no contract code changes (`main` does not currently compile, see below).

## #513 withdraw event

What existed: `withdraw` already emits `SmeWithdrew` (topics `sme_wd`, `invoice_id`; data `amount` = the escrow's `funded_amount`, `recipient` = `sme_address`) after the token transfer. `docs/EVENT_SCHEMA.md` listed it but its data table omitted `recipient`; `docs/escrow-events.md` did not mention it.

Done:
- `docs/escrow-events.md`: new `SmeWithdrew` section in the file's existing format (topics, data payload, decoded JSON example)
- `docs/EVENT_SCHEMA.md`: added the missing `recipient` (`Address`) row to the `SmeWithdrew` data table

Not done in this PR:
- A separate `WithdrawnEvt` with `sme`, `amount`, `ledger_timestamp` (the existing `SmeWithdrew` covers sme and amount but has no timestamp)
- SDK `WithdrawnEvent` type, event tests

## #511 Prevent `claim_investor_payout` before settlement

Found: `claim_investor_payout` already rejects unsettled escrows (`InvestorClaimNotSettled`) and does not compute a payout itself; `compute_investor_payout` returns 0 when `FundingCloseSnapshot` is absent.

Not done in this PR: the explicit snapshot guard, `SnapshotMissing` (code 24), docs, test.

## #512 `get_payout_preview`

Found: `compute_investor_payout(investor)` is an existing auth-free read that returns 0 before settlement.

Not done in this PR: the preview entrypoint, SDK wrapper, tests, docs.

## #514 Single-withdraw semantics

Found: `withdraw` requires `status == 1` and sets `status = 3`, so a second call already fails with `WithdrawalNotFunded`.

Not done in this PR: `WithdrawnFlag`, `AlreadyWithdrawn` (code 25), docs, tests.
