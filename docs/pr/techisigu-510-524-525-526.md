## Summary

Adds the `trace_tier_selection <lock_secs>` command to the REPL CLI (#524, first scope item). This PR implements that single instruction; #510, #525 and #526 are referenced but not implemented here.

## #524 Yield tier selection trace in the REPL CLI

What existed: `repl-cli` has mock-backed inspection commands (`get_escrow`, `get_version`, `export_state`, ...); nothing showed how a commitment maps onto the tier table.

Done:
- `trace_tier_selection <lock_secs>` (also `trace-tier-selection`) prints the base yield and one line per tier: `tier <i>: min_lock_secs <n>, yield <bps> bps: qualifies | does not qualify`
- Qualification mirrors the contract's `effective_yield_for_commitment`: a tier qualifies when `lock_secs >= min_lock_secs`, and `lock_secs = 0` (no commitment) qualifies for none; an empty table prints that the base yield applies
- Like the other commands it uses mock data without `--contract` (base 500 bps as in the mock `get_escrow`, tiers at 30 / 90 / 180 days) and returns the "not connected to live RPC yet" error otherwise
- Invalid or missing `lock_secs` gives a clear error; `help trace_tier_selection` and the command list document it
- Unit tests for the formatter (per-tier lines, lock equal to `min_lock_secs`, zero lock, no table) and for argument parsing

Not done in this PR:
- Highlighting the selected tier in the output
- `repl-cli/README.md` documentation

Verification: `repl-cli` is not a member of the root workspace (`cargo build` in it fails with "current package believes it's in a workspace when it's not", on `main` too). Tested in a scratch copy with an empty `[workspace]` table added: `cargo test` 5/5, and a piped REPL session (`trace_tier_selection 7776000`, `0`, `x`, `help trace_tier_selection`) prints the expected output. No `rustfmt` differences added (the file has 3 pre-existing ones).
